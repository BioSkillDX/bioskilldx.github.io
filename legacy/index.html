Problem

なぜ必要か

プロトコルに書かれない知識

生命科学実験には再現性の課題があります。実験プロトコルに書かれている手順を辿っても、同じ結果が得られるとは限りません。条件のわずかな違いが実験の成功率に大きく影響します。

熟練者は、試料の状態を見て「どこが勘所か」「何を変えるべきか」を判断しながら進められるため成功率が高い。一方、初学者はその判断に必要な情報にアクセスしにくく、同じ手順を実行しても失敗しやすい。

この問題の多くは、実行に必要な情報がプロトコルに十分に含まれていないことに起因します。BioSkill-Legacyは、この空白を埋めることを目的としています。

観察に基づく判断

サンプルの色・粘性・泡立ちなどを見て、次の工程の条件を分岐させる

経験則による調整

数値化されていないが、成功率を左右する微妙なチューニング

文脈依存の手技

環境・機器・試薬ロットに応じた、その場でしか判断できない微調整

Two Pillars

何をするか

Pillar A

"書くべきこと"の確立

プロトコルに「書かれるべき項目」と「根拠」を確立する

  • 実験プロトコルに含めるべき「記載すべき項目」の定義
  • なぜそれが必要か（根拠）の体系化
  • スタイルの議論ではなく、内容（what / why）にフォーカス
  • LLM等による整形・テンプレート化は項目確定後に加速
Pillar B

判断プロセスの
記録とモデル化

熟練者の判断（メンタルモデル）を、ワールドモデルへ接続する

  • 観察 → 判断 → 介入 → 結果 のチェーンを記録
  • 操作対象物の状態変化に着目（手先の動きだけでなく）
  • アフォーダンスに基づく記録単位の設計
  • 将来的なワールドモデル構築への接続

Structure

どう動くか

A

パートナーシップ / ブランディング

上流

熟練者・研究室・企業との関係構築。LEGENDSレクチャー、Troubleshooting Night、Lab Hero Stories による発信と協力者の獲得。

B

データ収集

現場

熟練研究者による実験の実施・聞き取り・多視点撮影を一体で実施。俯瞰・側面・対象クローズアップ・プロトコル画面・音声を同時取得。

C

データ整備 / アーカイブ

基盤

データスキーマ（メタデータ、手順ID、機材情報、環境条件等）の整備。保存・検索・再利用の可能性を担保する。

D

解析 / モデル化

下流

不記載情報を質問群・項目群・根拠として構造化。動画・注釈・結果指標との紐づけと、再利用可能な表現への変換。

Benefits

誰に何が届くか

熟練研究者

  • 判断基準や工夫が「再現可能な形」で記録される
  • 後進育成の負荷を下げる
  • 協力内容がケーススタディ・教材として可視化される

研究室・チーム

  • 不記載情報の整理で再現性・立ち上げ速度が向上
  • 属人化した手順が明文化され引き継ぎコスト削減
  • トラブル原因の切り分けが進む

若手研究者・学生

  • 成功基準・失敗兆候・条件分岐を含む教材にアクセス
  • "判断の理由"が注釈・根拠とともに得られる
  • 学習曲線が短くなる

企業・メーカー

  • 現場の詰まりポイントがデータとして得られる
  • 製品改善や新規提案に繋がる
  • 実験環境全体の改善検討に接続
