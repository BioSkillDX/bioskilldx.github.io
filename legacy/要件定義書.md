# BioSkill-Legacy ウェブサイト 要件定義書

**バージョン**: 0.1.0（内部レビュー用ドラフト）
**作成日**: 2026-03-24
**ベースドキュメント**: BioSkill-Legacy ホワイトペーパー v0.1.3（2026-02-15）

---

## 1. プロジェクト概要

### 1.1 目的

BioSkill-Legacy の活動内容・ビジョン・参加方法を伝えるウェブサイトを、BioSkillDX 公式サイト（`bioskilldx.github.io`）のサブディレクトリ `legacy/` に構築する。

### 1.2 ターゲットユーザー

| ユーザー | 主な関心 |
|---|---|
| 熟練研究者 | 自身の技能を遺産として残す意義、参加方法 |
| 研究室・チーム | 再現性向上、属人化の解消 |
| 若手研究者・学生 | 学習資源としての価値 |
| 企業（装置・消耗品メーカー） | 現場データへのアクセス、製品改善への接続 |

### 1.3 スコープ

**本フェーズ（v1）に含むもの**:
- `legacy/` ディレクトリ内の新規ファイル作成のみ
- 日本語のみ（単言語）
- シングルページ構成（セクション分割）

**本フェーズに含まないもの**:
- 既存サイト（`index.html`, `sitemap.xml`, `translations.js` 等）への変更
- 英語対応（後日対応）
- 独自ドメイン・独自ホスティング

## 2. コンテンツ設計

### 2.1 セクション構成

白書の10項目をウェブ向けに8セクションに再構成する。

| # | セクションID | セクション名 | 白書の対応箇所 | コンテンツ概要 |
|---|---|---|---|---|
| 1 | `#hero` | ヒーロー | — | キャッチコピー + プロジェクト概要1文 + CTA |
| 2 | `#problem` | 課題 | §1 背景, §3 仮説 | 再現性問題と暗黙知の正体（書けない/書かない/書き忘れ） |
| 3 | `#mission` | ミッション | §2 位置づけ | 暗黙知→遺産への変換ビジョン。Data / Model / Operation の3軸 |
| 4 | `#pillars` | 二つの柱 | §4 二つの柱 | A「書くべき項目の確立」/ B「判断プロセスのモデル化」 |
| 5 | `#structure` | 実行体制 | §5 体制, §6 データ戦略, §7 運用ループ | 4ロール図解 + 運用ループ |
| 6 | `#benefits` | メリット | §8 メリット, §9 アウトプット | 4ステークホルダー別のメリットカード |
| 7 | `#action` | 参加する | §6 参加導線, フォーム, YouTube | 投稿フォーム（β）CTA + 参加形態の説明 |
| 8 | `#team` | チーム | 著者 | コアメンバー5名 |

### 2.2 各セクション詳細

#### #hero（ヒーロー）
- **キャッチコピー**: 「熟練者の"技"を、未来への"遺産"に」
- **サブテキスト**: BioSkill-Legacy の1文概要（白書§2 ミッションから要約）
- **CTA ボタン**: 「詳しく見る」→ `#problem` へスクロール
- **背景**: 微パープル系 `#F6F4F8`

#### #problem（課題）
- **見出し**: 「Problem」
- **構成**:
  - 左カラム: 問題提起テキスト（2〜3段落）
    - 同じプロトコルでも結果が異なる理由
    - 暗黙知 = プロトコルに不記載の情報全体
  - 右カラム: 暗黙知の3カテゴリをカード形式で表示
    - 観察に基づく判断（サンプルの状態を見て条件分岐）
    - 経験則による調整（数値化されていないチューニング）
    - 文脈依存の手技（環境・機器に応じた微調整）

#### #mission（ミッション）
- **見出し**: 「Mission」
- **構成**:
  - 中央揃えのステートメント: 暗黙知を「遺産」に変換する
  - 3つのキーワードをアイコン付きで横並び:
    - **Data** — 収集・記録
    - **Model** — 構造化・モデル化
    - **Operation** — 活用・更新

#### #pillars（二つの柱）
- **見出し**: 「Two Pillars」
- **構成**: 2カラムレイアウト
  - **Pillar A カード**: 「"書くべきこと"の確立」
    - プロトコルに含めるべき項目とその根拠の定義
    - スタイルではなく内容（what / why）にフォーカス
  - **Pillar B カード**: 「判断プロセスの記録とモデル化」
    - 観察 → 判断 → 介入 → 結果 のチェーン
    - メンタルモデル → ワールドモデルへの接続
    - アフォーダンスに基づく記録単位の設計

#### #structure（実行体制）
- **見出し**: 「Structure」
- **構成**:
  - 4ロール図解（上流→下流のフロー）:
    - A. パートナーシップ / ブランディング（上流）— LEGENDS講義、投稿企画
    - B. データ収集（現場）— 実験実施 + 聞き取り + 多視点撮影
    - C. データ整備 / アーカイブ（基盤）— スキーマ、メタデータ、保存・検索
    - D. 解析 / モデル化（下流）— 構造化、動画・注釈・結果指標の紐づけ
  - 運用ループ循環図:
    - 抽出 → 構造化 → 記録 → 紐づけ → 更新
- **注記**: 図解はまずテキスト+簡素なリストで成立させ、SVG/CSS図は段階的に追加

#### #benefits（メリット）
- **見出し**: 「Benefits」
- **構成**: 2×2 グリッドのカード
  - **熟練研究者**: 判断基準・工夫が再現可能な形で残る / 後進育成の負荷軽減 / クレジット表記
  - **研究室・チーム**: 不記載情報の整理→再現性向上 / 属人化解消→引き継ぎコスト削減
  - **若手研究者・学生**: 成功基準・失敗兆候を含む教材 / 判断の理由が注釈付きで得られる
  - **企業・メーカー**: 現場の詰まりポイントがデータ化 / 実験環境改善への接続

#### #action（参加する）
- **見出し**: 「Get Involved」
- **構成**:
  - 投稿フォーム（β）への CTA ボタン
  - 3つの投稿カテゴリの簡潔な説明:
    - **Troubleshooting Night** — 失敗談・ヒヤリハット
    - **Lab Hero Stories** — 困りごとの解決事例
    - **Lab Hacks & Gear** — 実験の工夫・機材Tips
  - 参加の段階（ライト参加 → データ提供 → 共同検証 → 拠点利用）
  - YouTube チャンネルへのリンク（月次フィードバック配信）

#### #team（チーム）
- **見出し**: 「Team」
- **メンバー**: 笹川洋平、大田達郎、小野浩雅、二階堂愛、藤江学
- **表示**: 名前 + 所属（写真は後日追加可能な構造にしておく）

### 2.3 フッター
- BioSkillDX ロゴ + 「Legacy」表記
- ページ内セクションへのリンク
- 外部リンク: YouTube、GitHub、投稿フォーム
- BioSkillDX 親サイトへのリンク
- コピーライト

## 3. デザイン要件

### 3.1 デザインシステム（親サイトからの継承）

| 要素 | 仕様 |
|---|---|
| フォント | Lato（英語）+ Noto Sans JP（日本語）— Google Fonts |
| ベーステキスト色 | `#333` |
| 背景色 | `#fff`（主）, `#f8f8f8`（セクション交互） |
| コンテナ幅 | `max-width: 1200px` |
| レスポンシブ | 1024px（タブレット）, 768px（モバイル） |
| アニメーション | fade-in（Intersection Observer, `translateY(30px)`, `0.8s ease`） |
| ヘッダー | 固定、glass morphism（`backdrop-filter: blur(10px)`） |
| ボタン | `border-radius: 50px`、グラデーション背景 |

### 3.2 サブブランドカラー

親サイトのパープル（`#AC93C8` = 技術・AI）との差別化として、**ゴールド/アンバー系**を採用。「知の継承・遺産・人間の営み」を表現する。

```
アクセント:       #C8A86A（ゴールド）
アクセント（暗）: #A88C52（ホバー・アクティブ）
グラデーション:   linear-gradient(135deg, #C8A86A, #A88C52)
ヒーロー背景:    #F6F4F8（微パープル）
```

**注意事項（プレモーテムより）**:
- ゴールドはアクセント（線・ドット・ボーダー）に限定し、面塗りは控える
- 実装後に複数デバイスで色味を確認すること
- 必要に応じてパープルをメインに残しゴールドをセカンダリにする判断もあり得る

### 3.3 親サイトとの差別化

| 要素 | 親サイト (BioSkillDX) | Legacy |
|---|---|---|
| アクセントカラー | パープル `#AC93C8` | ゴールド `#C8A86A` |
| ヒーロー背景 | 白 + GIFアニメ | 微パープル `#F6F4F8` |
| ロゴ表記 | BioSkillDX | BioSkillDX ロゴ + "Legacy" テキスト |
| 言語切替 | JA / EN | なし（v1は日本語のみ） |

## 4. 技術要件

### 4.1 技術スタック

- HTML5（セマンティック）
- CSS3（カスタムプロパティ、Grid、Flexbox）
- Vanilla JavaScript（フレームワークなし）
- ホスティング: GitHub Pages（`bioskilldx.github.io/legacy/`）

### 4.2 ファイル構成

```
legacy/
├── index.html              # メインページ（シングルページ）
├── css/
│   └── legacy.css          # Legacy固有スタイル
├── js/
│   └── legacy.js           # インタラクション
└── img/                    # 画像（後日追加）
```

### 4.3 CSS 方針

- 親サイトの `css/style.css` とは**独立**（import しない）
- 共通コンポーネント（reset, header, footer, fade-in, container, button, responsive）は親CSSからコピーして取り込む
- Legacy 固有のセクションスタイルを追加
- 将来的に `css/common.css` への共通化リファクタリングの余地を残す

**注意事項（プレモーテムより）**:
- 親サイト更新時に Legacy 側のヘッダー/フッターが乖離するリスクがある
- 統合フェーズで共通CSS切り出し、または親CSSを読み込む方式への移行を検討

### 4.4 JavaScript 機能

- ヘッダーのスクロール時シャドウ追加（`is-scrolled`）
- モバイルハンバーガーメニュー（開閉 + オーバーレイ）
- セクションへのスムーススクロール
- fade-in アニメーション（Intersection Observer）
- スクロール進捗バー（ページ上部のゴールドプログレスバー）

### 4.5 ナビゲーション

**ヘッダー構成**:
```
[BioSkillDXロゴ + "Legacy"]  Problem | Mission | Pillars | Structure | Benefits | Action | Team  [← BioSkillDX]
```

- ロゴクリック → 親サイト (`../index.html`) へ遷移
- 右端に「BioSkillDX トップへ」リンク
- ページ内リンクはスムーススクロール

### 4.6 SEO / メタデータ

- `<title>`: BioSkill-Legacy - 生命科学実験の暗黙知を遺産に
- OGP タグ（og:title, og:description, og:image, og:url）
- Twitter Card（summary_large_image）
- JSON-LD（ResearchProject）
- canonical URL: `https://bioskilldx.github.io/legacy/`

### 4.7 レスポンシブ対応

| ブレークポイント | レイアウト変更 |
|---|---|
| > 1024px | フルレイアウト（2カラム、グリッド） |
| 768px〜1024px | カラム縮小、間隔調整 |
| < 768px | シングルカラム、ハンバーガーメニュー、フォントサイズ縮小 |

## 6. 制約事項

### 6.1 本フェーズの制約
- 既存サイトのファイルは**一切変更しない**（内部レビュー段階のため）
- 画像素材は後日追加（HTML構造としてプレースホルダーを用意）
- 英語対応は後日（`data-i18n` 属性は仕込まない）

### 6.2 コンテンツに関する注意
- 白書はドラフト（v0.1.3）であり、ウェブ公開範囲について著者の合意確認が必要
- ウェブ用に表現を簡潔化した箇所は、レビュー時に著者に差分を提示する

### 6.3 後続フェーズで対応する事項
- 親サイトのナビゲーション・フッターへの Legacy リンク追加
- `sitemap.xml` への Legacy ページ追加
- `translations.js` への翻訳キー追加
- 英語対応
- CSS 共通化リファクタリング
- OGP 画像の制作

## 7. 検証方法

1. ローカル HTTP サーバーで全セクションの表示確認
2. レスポンシブ: Chrome DevTools で 375px / 768px / 1024px / 1440px を確認
3. モバイルメニューの開閉・セクションスクロール動作
4. 外部リンク（Forms, YouTube, GitHub）の遷移確認
5. 親サイト → Legacy のリンク（後続フェーズ）
